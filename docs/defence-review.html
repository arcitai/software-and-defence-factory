Løbende sikkerhed.
Fra fund til verificeret løsning.

OpenAIs definition flytter vores fokus mod proaktiv sikkerhedsundersøgelse. Din idé om overvågning og incidents passer ind som en tilsluttet driftsdel.

To ansvar. En fælles vej til rettelsen. Software Factory ejer udvikling og levering. Defence Factory følger sikkerhedsrisiko på tværs af livscyklussen. Begge kan arbejde før og efter en release.

Sådan foreslår jeg, vi deler arbejdet

Vores produktforslag — ingen bestemt agent, cloud eller model er påkrævet
DelAnsvar og eksempel
Software FactoryByg og lever ændringer med security, tests og review. Fx en ny bookingfunktion eller en sikkerhedsrettelse.
Defence FactoryUndersøg systemet, validér fund, prioritér og følg løsningen. Fx kontrollér adgang mellem kunder, selv om ingen alarm er udløst.
Tilsluttet driftBrug eksisterende uptime, logs, alarmer og beredskab. Driftsproblemer og dependency-signaler kan starte en sag.

Defence kan også tilsluttes gammel software og leverandørløsninger. Modtageren af en rettelse kan være vores Software Factory, det eksisterende team eller leverandøren.

Det betyder for vores setup

Selvstændige løsninger. Del security-kontekst, sager og beviser; repo-/runtimeopdeling afklares senere. Codex Security er en mulig specialist; andre agenter og lokale modeller skal kunne kvalificeres til samme opgave.

Dokumenteret værdi. Mål relevante validerede fund, støj, tid til faktisk udbedring, regressioner, direkte udgifter og mennesketid. Bevar ukendt dækning synligt.

Status: research og revideret forslag. Det lokale alarm-replay er kun en operations-prototype; discovery, sikkerhedsvalidering og live drift er endnu ikke tilsluttet.
