Factoryen arbejder i skyen.

Du behøver ingen kraftig lokal computer. Udviklingen følger stadig vertical slices: én lille funktion fra ende til ende, afprøvning og derefter næste del.

Hurtig pilot: Codex Cloud. Åben produktprofil: Pi i en cloud-sandbox. Start manuelt med dit eksisterende abonnement, hvis cloudadgangen er tilgængelig. Byg derefter én Pi/Daytona-forbindelse til vores dashboard. Samme metode, krav og målinger; model og hosting kan skiftes.

Hvad bruger vi til hvad?

Forslag til vores åbne cloudprofil · integrationen skal bygges
DelValg og opgave
Opgaver og kodeGitHub. Issues, branches og PR’er er arbejdsgrundlaget.

Det er kun styringen, der skal være tændt hele tiden. Agentcomputeren starter ved opgaver. Ingen egen GPU er nødvendig, når modellen leveres via en API.

Tre vigtige afklaringer

Codex Cloud er genvejen

En manuel pilot kræver ingen egen server. Cloud og lokal Codex deler dog abonnementsgrænser. Eget dashboard via Agents API er en særskilt, API-afregnet integration.

Cloudroom er inspiration

God model for jobs, der overlever en afkoblet klient. Men selvhosting tilføjer Linux-drift, Rust og PostgreSQL. Vi overtager principperne og beholder vores lille kerne.

Compute er kun én udgift

Daytona-eksempel: 2 vCPU + 4 GiB i 20 timer ≈ $3,31. Model, disk, controller og øvrig drift kommer oveni. Ingen samlet prisbesparelse er målt.

Cursor er et alternativ, hvis færdig browser/desktop sparer opsætning. Vi bygger én cloudadapter først. Se alternativer, prisgrundlag og Cloudroom-gennemgang.

Hvad findes allerede?

Bygget: lokalt dashboard, opgaver, GitHub-læsning, journal, stop og evidensimport. Syntetisk afprøvet: Pi og Security. Mangler: fjernworker, automatisk jobforløb og rigtige pilotmålinger. Cloudprofilen er endnu en plan.

Næste byggetrin · tre vertical slices

1 / Én opgave gennem skyenForberedt opgave → Pi-sandbox → synlig reviewpakke. Med fast revision, adgangsgrænser, timeout og stop fra første slice.

2 / Afbryd og kom tilbageGenfind jobbet efter mistet forbindelse eller genstart. Ingen dobbelt worker, tabte beviser eller nulstillet budget.

3 / Tilslut GitHub-flowetEn godkendt issue følger samme vej til PR og review. Derefter tre Kastanje-opgaver, inklusive videreudvikling af tidligere kode.

Behov → arkitektur → kodevalg → små fungerende dele. Afprøv hver del, gem beviser og fortsæt inden for aftalt scope. Ukendt status eller pris skal være synlig.
