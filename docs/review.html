En factory til dine eksisterende apps.

En fælles metodepakke, som kan lægges ind i appens repo. Du vælger agent, model og driftsmiljø. Appens arkitektur og deployment bevares.

GitHub kan være hele kontrolpanelet. Opret issues, følg checks og læs PR’er. Skills beskriver arbejdet; den valgte integration starter agenten. Egen runner, cloud-sandbox og vores dashboard er tilvalg.

Hvad definerer vi — og hvad vælger appen?

Actions gør det velkendte

Tests og CI

TDD i udviklingen; CI genkører rigtige tests, build og relevante hurtige sikkerhedschecks før integration.

Deployment

Brug appens eksisterende CD eller hostingintegration, med dens rettigheder, miljøer og rollback.

Agentarbejde

Kører i det valgte agentmiljø. Lange jobs behøver ikke optage en GitHub-hosted runner, mens vi venter.

Lavprisvalg: egne Actions-runners bruger ikke hosted-minutpuljen efter de aktuelle regler. En egnet lokal model kan også fjerne API-regningen. Maskinen skal være tændt; strøm, drift, lager og apphosting tæller stadig. Runnerregler og Codex Security i CI.

Samme pakke, forskellige installationer

Mac + cloudabonnementBrug udbyderens agentmiljø og integration. GitHub er arbejdsfladen. Ingen egen controller, hvis tjenesten dækker behovet.

Z13 + lokal modelAgent og eventuelt CI kører på din egen tændte maskine. Afprøv model, værktøjer og afgrænset arbejdsmiljø.

Egen skyValgt agent på egen VM eller sandbox. Cloudroom er inspiration til drift; ingen bestemt runtime er produktkrav.

Hvad ligger klar nu?

Eksportérbar pakke: seks skills, fælles regler, installationsark, aflevering/målinger, issue-form og inaktivt CI-eksempel. Eksporten overskriver ikke appens filer. Den lokale runner og dashboardet er bevaret som tilvalg.

Næste prøve: tilslut én eksisterende app med dens valgte agent og CI → gennemfør én lille vertical slice → review faktiske beviser. Automatisér derefter et konkret gentaget trin. Ingen provider er forhåndsvalgt.
